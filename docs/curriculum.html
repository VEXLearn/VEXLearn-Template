VEXLearn Foundations

From First Code to Reliable Autonomous

Pilot Version Eight Modules 10-14 Hours

VEXLearn Foundations is a beginner curriculum for learning VEX V5 programming through documented, editable robot code. Students progress from basic C++ and robot configuration to driver control, PID movement, autonomous programming, and reliability testing.

The curriculum can be completed as a code-reading pathway without a robot or as a complete hardware pathway using a compatible tank-drive VEX V5 robot.

Intended Audience

  • Students with little or no previous C++ experience
  • New VEX programmers
  • Teams transitioning from block coding to text-based programming
  • Mentors teaching beginner VEX V5 software
  • Students who want to understand robot code before moving to more advanced frameworks
ⓘ
Recommended duration

Complete the eight modules over approximately 10-14 hours. A school club could complete one module per meeting. Modules 5 through 7 may require multiple meetings because physical tuning and autonomous testing take time.

Two Completion Pathways

Code Learning Path

No physical robot is required. Students read, trace, modify, and explain the VEXLearn source code. They complete Modules 0-4, code-reading versions of Modules 5-7, and a written capstone design.

Robot Programming Path

Students complete every module, physical testing, and the autonomous capstone using a compatible tank-drive VEX V5 robot, separate left and right motor groups, a V5 inertial sensor, the official VEX VS Code extension, and a safe testing area.

Module 0: Orientation and Baseline

30-60 minutesBoth pathways

Learn what VEXLearn is designed to teach, understand its limitations, locate the major source files, choose a pathway, and complete a baseline assessment.

Required Reading

  • VEXLearn homepage
  • Requirements
  • Setup Guide
  • Learning Only vs. For Use

Activities

  1. Download the latest release.
  2. Open the correct inner project folder in VS Code.
  3. Locate main.cpp, robotConfig.cpp, drive.cpp, movement.cpp, auto.cpp, and display.cpp.
  4. Complete the pre-course assessment.
  5. Write one sentence describing the purpose of each source file.

Evidence and Checkpoint

Submit a completed setup checklist, baseline score, six-file project map, and selected pathway. Pass by correctly matching at least five of the six major source files with their purpose.

Module 1: C++ Fundamentals for VEX

90 minutesBoth pathways

Identify common data types, declare and update variables, use operators, read control structures, explain function signatures, and distinguish declarations from definitions.

Required Reading

Data Types, Variables, Operators, Loops and If-Statements, Functions, Header Files, File Integration, and Namespaces.

Activity 1: Predict the Result

Predict the final value before running or checking this code:

int speed = 5;
speed += 2;

if (speed > 6) {
    speed = 6;
}

Activity 2: Repair the Code

Correct at least five errors involving missing semicolons, incorrect variable types, assignment versus comparison, misspelled function names, and missing header declarations.

Activity 3: Write a Function

double limitVoltage(double requestedVoltage, double maximumVoltage);

The function must return a value that does not exceed the positive or negative maximum.

Evidence and Checkpoint

Submit the corrected exercise, completed function, a short explanation of declaration versus definition, and the module quiz. Score at least 75% on the quiz.

Module 3: Robot Configuration and Driver Control

90 minutesBoth pathways

Configure motors and sensors, modify motor groups and driver behavior, change controller mappings, and use a Boolean variable to toggle a mechanism.

Required Reading

Robot Setup Checklist, How Ports Work, Gear Ratio and Software, 6-Watt versus 12-Watt Motors, robotConfig.cpp, and drive.cpp.

Activity 1: Configure the Robot

Hardware-path students update motor ports, directions, groups, sensor and piston ports, wheel diameter, and external gear ratio. Code-learning students create a hypothetical six-motor tank-drive configuration.

Activity 2: Change Driver Preferences

Modify at least two of the following: deadband, controller sensitivity, coast-to-brake timing, button mapping, or mechanism speed.

Activity 3: Add a Mechanism Toggle

Implement or modify a Boolean-based controller toggle for a piston or another mechanism.

Evidence and Checkpoint

Submit a configuration commit or saved code copy, explain two modifications, and record the compilation result and hardware demonstration when available. The program must compile, or the student must correctly identify and explain the remaining compilation problem.

Download configuration planner

Module 4: Autonomous Movement

90 minutesBoth pathways

Explain auto.cpp, use move() and turn(), understand their arguments, plan routes, and recognize when an advanced odometry-based template is more appropriate.

Required Reading

Absolute Heading, Voltage versus RPM Control, Writing Autonomous Functions, movement.cpp, and auto.cpp.

Activity 1: Read Movement Calls

move(100, 0, 8);
turn(90, 6);
move(50, 90, 6);

Explain the expected behavior of each line, including distance, heading, and voltage.

Activity 2: Plan a Route

Draw a route with a starting position, distances, headings, mechanism actions, and expected ending position.

Activity 3: Write a Three-Step Routine

Include at least one move(), at least one turn(), and at least one additional movement or mechanism action.

Evidence and Checkpoint

Submit the route diagram, autonomous source code, and an explanation of every movement argument, followed by a code review or physical demonstration. Explain what the robot should do without running the program.

Module 5: PID Tuning Laboratory

2-3 hoursHardware testing recommended

Explain proportional, integral, and derivative control; identify windup, overshoot, oscillation, and steady-state error; and select tuning values using controlled evidence.

Required Reading

PID Controller, Integral Windup, Interactive PID Demo, Voltage versus RPM Control, and the PID sections in movement.cpp.

Laboratory Rules

  • Use the same starting position, target distance, and maximum voltage.
  • Change only one PID value at a time.
  • Record battery percentage for every trial.
  • Use a physical starting aligner and record trials on video when possible.

Activities

  1. Adjust Kp and record response speed, overshoot, final error, and oscillation.
  2. Adjust Kd and observe changes in oscillation and overshoot.
  3. Explain integral accumulation, voltage saturation, and why accumulated error resets after crossing the target.
  4. Justify final constants using at least three recorded trials.

Module 6: Reliability, Debugging, and Testing

90 minutesHardware testing recommended

Separate software from hardware failures, use repeated trials, record failure conditions, evaluate environmental factors, and revise code using testing evidence.

Required Reading

Writing Autonomous Functions and the stopping and timeout behavior in movement.cpp.

Activities

  1. Classify failures as configuration, compilation, control logic, sensor, mechanical, starting-position, battery or power, or unknown.
  2. Run the same autonomous routine ten times and record success, ending error, battery, failure category, and notes.
  3. Identify the most frequent failure, make one change, and complete five more trials.

Evidence and Checkpoint

Submit the ten-run baseline, one documented revision, five-run retest, before-and-after success rate, and a short failure analysis. Explain why one successful run does not prove an autonomous routine is reliable.

Module 7: Final Autonomous Capstone

2-4 hoursFinal project
✓
Challenge

Design, program, test, and explain a short autonomous routine using the VEXLearn template.

Minimum Requirements

  • At least three movement commands and one turn
  • At least one mechanism action when hardware permits
  • A planned starting position and route diagram
  • A safe timeout or bounded movement behavior
  • At least ten documented physical trials for the Robot Programming Path

The Code Learning Path submits the complete route, code, predicted behavior, and testing plan without physical trial results.

Required Submission

  1. Route diagram
  2. Source code
  3. Hardware configuration
  4. PID values
  5. Trial log
  6. Short demonstration video
  7. Failure analysis
  8. Final reflection

Reflection Questions

  • What part of the routine was least reliable?
  • Which change produced the largest improvement?
  • What evidence supports your final PID values?
  • What hardware behavior affected the software?
  • What would you change with another week?
  • When would a more advanced framework such as JAR Template or LemLib become appropriate?

Performance Levels

  • 90-100: Independent. The student can configure, program, test, explain, and improve the system with little assistance.
  • 75-89: Proficient. The student completes major tasks but needs occasional guidance while debugging or tuning.
  • 60-74: Developing. The student understands basic concepts but needs substantial support with configuration, debugging, or autonomous testing.
  • Below 60: Incomplete. The student should revisit modules connected to missing or incorrect capstone elements.

Pre-Course and Post-Course Assessment

Use the same concepts before and after the curriculum, but change numerical values and code examples so the post-test does not reward memorizing answers.

  1. What is the difference between int, double, and bool?
  2. What does == mean, and how is it different from =?
  3. What does a while loop do?
  4. What is the purpose of a header file?
  5. Where are VEX motors and sensors configured?
  6. What does the heading argument in move() control?
  7. Why must the software gear ratio match the physical drivetrain?
  8. What does the proportional term of PID respond to?
  9. What is integral windup?
  10. Why should an autonomous routine be tested multiple times?
  11. Name two non-software factors that can change autonomous performance.
  12. When should a team consider moving from VEXLearn to an odometry-based template?

Questions 1-6 are worth one point each. Questions 7-12 are worth two points each, for 18 points total. Record initial and final scores, percentage-point improvement, module completion, capstone score, autonomous trial success rate, and student confidence before and after.

Instructor Guidance

!

VEXLearn is designed to help students understand beginner VEX V5 software. Instructors should ask students to explain code before copying or modifying it. Physical movement activities must be conducted in a clear testing area with the robot raised or restrained during initial mechanism tests.

The curriculum prioritizes understanding, testing, and documentation over achieving one universal performance threshold. Different robots require different PID values and tolerances.
